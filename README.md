# 金縢（jinteng）

自托管的**凭据单源**：一条凭据只存一份，你的多台机器（macOS／Windows／WSL2／Linux）各自取用同一份。
单个 Go 二进制，服务端不依赖数据库、反向代理或账号体系。

完整部署与使用手册：<a href="deploy.html">deploy.html</a>（含 systemd＋tmux 运行形态、各端接入、备份恢复、
故障排查与安全边界）。本页只给最小上手路径。

## 安全模型

- **客户端零长期持钥**：每把凭据有自己的数据密钥（AES-256-GCM），按端做 X25519 封装;客户端静息材料
  离开本机后既读不了库也解不开密文，也无法伪造请求签名。
- **解锁要两个人在场条件**：设备私钥文件由 `Argon2id(口令 ‖ 机器指纹)` 封存。口令不在场解不开，
  材料搬到别的机器也解不开。没有恢复机制——忘记口令等于该端材料作废。
- **服务端只见密文与事件**：凭据内容以不透明密文存放；取用事件只记「时间／设备／动作／结果／凭据名盲索引」
  五个字段，不含凭据内容。凭据名在服务端也不以明文落盘。
- **每个跨机请求必须签名**：Ed25519 签名覆盖方法、路径、查询串与请求体，带时间窗与一次性 nonce 防重放;
  撤销、登记、名录读取同样受签名保护。

## 快速上手

```bash
# 服务端（首次启动会自签 TLS 证书并打印一枚 SHA-256 指纹，各端要人工核对固定）
make build
bin/jinteng serve -listen <本机可路由地址>:8787      # 不接受 0.0.0.0／::

# 同一终端里发一枚一次性配对码（10 分钟有效、用一次即废）
#   输入一行：pair

# 每台端
jinteng init -url https://<地址>:8787 -pin <指纹> -device <端 id> -pair <配对码>
jinteng put  GIT_TOKEN <值>
jinteng run  -e GH_TOKEN=GIT_TOKEN -- gh auth status
```

命令面：`init`／`serve`／`put`／`get`／`delete`／`run`／`devices revoke`／`pair new|list|revoke`／`usage`。
`usage` 输出每台端的首次成功取用时间与统计窗口内的成功次数，用于观察「多端是否真在被使用」。

## 构建与验证

```bash
make test        # 全量单元测试
make e2e         # 本机端到端旅程，含「取用后工作目录零明文落盘」断言
make multidev    # 多端集成演练（三个机器指纹值＝三个独立端，serve 绑非回环）
make build-linux-amd64 build-darwin-amd64 build-darwin-arm64 build-windows-amd64
```

要求 Go ≥ 1.27，全部目标 `CGO_ENABLED=0`，无 CGO 依赖。

## 使用统计的口径（不粉饰）

`usage` 的分子可测（服务端计数），分母「本该取用却改用复制粘贴」系统看不见，所以比值输出为空;
样本为 0 时如实报 0，不给估计值。窗口内成功取用的端数不足时，读数会直接标注未达标并提示需复核前提。

## 已知边界

- 拥有服务端材料目录读取权限的人，能同时拿到库文件与库密钥——本产品只主张**材料离开本机即失效**。
- `put <值>` 与 `init -pair <码>` 走进程参数，对本机同权限可见。
- `delete <NAME>` 是硬删除：单事务移除该名的密文、名字密文与全部按端封装，产品内不可再取用；
  存储引擎空闲页不承诺物理擦除。任意在册未撤销端可删除已知名字，权限与写入／取用同级。
- 撤销是取用面的即时封锁且不重包密文：用同一对密钥重新登记会清撤销位并使旧副本复通，
  要彻底断绝内容仍需轮换凭据。网络面只能撤销自己那端，撤他端属服务器终端的操作员动作。
- 不做端侧缓存：服务端不可达即以专用退出码失败，绝不回吐旧值。
- 单用户单源：无多用户与权限模型，无移动端／Web 端。
